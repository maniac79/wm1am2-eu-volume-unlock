   SONY NW-WM1AM2 - EU VOLUME CAP TOOL 0.2.3
   ========================================

   READ FIRST - EXPERIMENTAL
   -------------------------
   *** NVRAM WRITES ARE DISABLED IN THIS BUILD ***

   Options 3 (apply), 4 (restore) and the advanced reference restore stop with
   exit code 13 and write nothing. Reason: on Android 11 one privileged request
   can execute more than once on the device, and that is not yet safe for
   writes. Options 1 (status), 2 (read) and 5 (reboot) work normally.
   Details: docs/ZYGOTE-SINGLE-EXECUTION.md in the repository.

   The project author reports a successful ORIGINAL MANUAL change on one
   NW-WM1AM2. The finished 0.2.3 macOS, Windows and Linux tools, automatic
   backup and backup-based restore have NOT been validated on physical hardware.
   Automated tests use simulated adb and a mock HAL. They are not a Walkman test.
   Only NW-WM1AM2, Android 11, Sony firmware 1.09.00 and fingerprint
   SonyAudio/icx1298_001/icx1298:11/1.09.00/68:user/release-keys are supported.

   This tool uses a temporary privilege escalation (CVE-2024-31317). No root
   and no bootloader unlock does NOT mean no exploit, no risk. The helper app
   remains installed until removed, and NVRAM changes persist across reboots.
   Eight NVRAM fields are written by Apply, Restore and reference restore.
   Writes are not atomic. A damaged partial write may not be recoverable by
   the ordinary Restore operation even with a valid backup.

   A snapshot of an already-modified player is NOT proof of the original EU baseline.
   A `baseline` label only means eight values matched the built-in reference
   profile observed on one EU unit. That match does not prove the historical
   values of your particular player. External original records, if any, need
   their own provenance check. `restore-reference` is not a factory restore.

   STEP 1 - Choose and check the download
   --------------------------------------
   On a published GitHub Release page, choose the versioned ZIP under Assets
   for YOUR computer: macOS, Windows or Linux. Do not choose GitHub's automatic
   "Source code" ZIP: it does not include the built APK. Match the ZIP SHA-256
   to the value printed OUTSIDE the ZIP in that release's notes. The internal
   SHA256SUMS.txt checks package contents but cannot establish publisher origin
   by itself. Check SOURCE-COMMIT.txt and the APK signer described in the
   repository's docs/SIGNING.md. If 0.2.3 Assets are not yet shown on the
   release page, wait for a package; do not substitute a source archive. The
   older v0.2.2 release remains available with known review findings.

   STEP 2 - Get adb and prepare the Walkman
   ---------------------------------------
   Get Android Platform Tools for your computer:
     https://developer.android.com/tools/releases/platform-tools
   Extract the platform-tools folder next to the START file, or add adb to PATH.
   The tool prefers the adjacent executable. You do not need the full Android
   SDK, JDK or Python to use a release ZIP. Use a USB cable that carries data.
   Windows may require a suitable USB driver; Linux may require USB access
   rules. These are troubleshooting possibilities, not hardware-tested claims.

   On the player: Settings > About device > tap Build number seven times;
   Settings > System > Developer options > enable USB debugging. Connect USB,
   accept "Allow USB debugging?" on the player and authorize this computer.
   In a terminal, `adb devices` should show exactly one entry marked `device`.
   `unauthorized` means the prompt was not accepted. Other connected ADB
   devices should be disconnected before using the tool.

   STEP 3 - Open the menu
   ----------------------
     macOS    double-click  START-macos.command
     Windows  double-click  START-windows.bat
     Linux    run           ./START-linux.sh

   A downloaded macOS script may produce a Gatekeeper prompt. Review the
   archive's published hash and source before choosing to open it. On Windows,
   START-windows.bat runs an unsigned local PowerShell script with an execution
   policy bypass; inspect the package first. A prompt does not prove safety.

   The menu has these actions on all three platforms:

     1) Status               read-only, no privilege, changes nothing
     2) Full NVP read        privileged read + verified backup
     3) Apply the change     back up first, then write
     4) Restore from backup  per-field restore, verified
     5) Reboot the player
     6) Requirements / where is adb
     7) Install/update bundled helper APK (no NVRAM write)
     0) Exit

   STEP 4 - First run and backup
   -----------------------------
   Choose 1 to view device, destination and safe_volume without installing an
   app or changing a device setting. Status does NOT verify firmware support;
   check the exact fingerprint separately. Then choose 7 to explicitly install
   or update the supplied APK. This changes the installed app, not NVRAM.
   Read and Apply never install it automatically. The menu does not uninstall
   an older helper. An Android signing-certificate mismatch stops the update;
   see docs/SIGNING.md before deciding whether to remove an old helper.

   Choose 2 to read all eight NVRAM values and save a verified backup. This is
   NOT a no-change dry run: it uses the privileged helper, a device lock, a
   temporary global setting and a local backup file. The setting is deleted
   and checked absent after the operation. Any pre-existing value (including
   literal null or empty), or an uncertain setting check, makes the command
   refuse before mutation. Do not delete a pre-existing value yourself merely
   to make the tool run.

   The backup path is printed. Preserve its .conf and .sha256 files together,
   preferably with a second private copy. The files contain device identity
   and raw values; do not post them publicly. `kind=baseline` means exact
   reference-profile match, `snapshot` means target-profile match, and
   `foreign` means another pattern. The first read of an already-modified
   player may be a snapshot. The backup format remains schema 1.

   STEP 5 - Writes and checks
   --------------------------
   Choose 3 only after reviewing the eight values and a recovery path for this
   exact player. Apply backs up first, then writes up to eight fields and reads
   each written value back. Choose 4 only with an appropriate validated backup;
   it writes fields individually. The advanced menu command `restore-ref`
   writes a built-in reference profile and needs explicit confirmation. None
   of these writes is a harmless test. Ordinary Restore may refuse a field
   whose current bytes are damaged or outside its accepted states.

   After a successful write, reboot before judging sound. Option 1 displays
   `safe_volume : 00000000` when vendor.safe_volume.enabled is zero, or
   `safe_volume : 01000000` for the EU-limited property. From a terminal:
     adb shell getprop vendor.safe_volume.enabled
   This property is not a measurement of sound level or proof of the loaded DAC
   table. Lower volume before listening, then raise it gradually. No dB change
   has been established.

   IF ANYTHING FAILS
   -----------------
   Exit 0 is the only complete success. Exit 3 means read/backup incomplete
   before the NVRAM write phase. Exit 4 means the data outcome is UNKNOWN;
   inspect the current state. Exit 5 allows a partial NVRAM state. Exit 7 means
   cleanup or lock release needs recovery, even if a data operation finished.
   Exit 11 is an unsupported profile/identity; 12 is a present or uncertain
   global setting, or an existing lock; 20 is an invalid/missing backup; 21
   means a non-baseline restore needs explicit file and consent.

   A failed cleanup keeps a protected local recovery record and device-wide
   lock. There is no automatic retry of failed cleanup. Do not blindly delete
   an unknown setting or a lock. Preserve the error, inspect the record and
   the player's state, and get help before another write. A completed readback
   still does not prove all values survived reboot.

   Firmware updates and factory resets are untested: recheck fingerprint and
   all eight values. This tool does not disable the Sony updater or Play Store.
   Do not automatically re-Apply after an update or reset. Those updates may
   carry security fixes. Report failures in GitHub Issues with version, host
   OS/architecture, firmware fingerprint, command and exit code, but redact
   serials, paths, backup contents and personal information.
